## Framework improvement hypothesis

### Hypothesis: split semantic framework authority from execution dependency identity

RAKL application fibres and TaskEpisode metadata should carry two separately typed references:

- `framework_semantic_authority_ref`: current framework state whose rules/semantics govern this research turn;
- `execution_dependency_pin_ref`: exact dependency version used for reproducible tests and historical receipts.

The system should fail closed if an agent tries to "update to the current framework" by rewriting a frozen execution pin or historical receipt without a separately governed migration packet.

### Expected benefit

- reduce false CI/provenance failures during framework evolution;
- allow research agents to adopt new reasoning semantics immediately while preserving reproducibility;
- make framework-upgrade cost visible as a process residual rather than contaminating mathematical state.

### Possible regression

If the two references are separated poorly, agents may reason using semantics that are incompatible with the executable library actually loaded for tests. Therefore the fibre should also record a compatibility/migration status.
